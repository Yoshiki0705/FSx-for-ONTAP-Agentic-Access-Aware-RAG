## 1. 业务 KPI

### 定义与测量方法

| KPI | 定义 | 目标（PoC） | 测量方法 |
|-----|------|------------|----------|
| 搜索时间缩短率 | 与传统手动搜索相比的时间节省 | 50%+ | 用户调查 + 时间戳比较 |
| 首次解决率 | 仅通过 AI 回答即可解决的比例 | 60%+ | 用户反馈（👍/👎） |
| 咨询减少率 | 帮助台咨询的减少量 | 30%+ | 前后工单数量比较 |
| 引用率 | 带有引用的回答比例 | 90%+ | 自动引用存在性汇总 |
| 权限违规次数 | 显示未授权文档的次数 | 0 | 权限矩阵测试 + 审计日志 |
| 月活跃用户率 | 注册用户中的月度使用率 | 70%+ | Cognito + 访问日志 |

### 测量仪表板

在 CloudWatch 仪表板（`enableMonitoring=true`）上可视化以下内容：

- 每日/每周搜索请求数
- 按用户的使用频率
- 回答生成成功率
- 平均响应时间（P50/P95/P99）
- Guardrails 干预率

## 2. RAG 质量指标

### 2.1 回答相关性

**定义**：生成的回答与用户问题的相关程度

**评估方法**：
- 人工评估：5 分制（1：不相关 – 5：完全相关）
- 自动评估：LLM-as-Judge（Claude 自动评分）

**目标**：平均 4.0+（5 分制）

### 2.2 忠实度

**定义**：生成的回答是否忠实于检索文档的内容（无幻觉）

**评估方法**：
- 将回答中的每个声明与引用文档交叉验证
- 测量无支持声明的比例

**公式**：
```
忠实度 = (有支持的声明数) / (回答中的总声明数)
```

**目标**：0.90+

### 2.3 上下文精度

**定义**：检索文档中实际对回答生成有贡献的比例

**评估方法**：
- 判断搜索结果中的每个文档是否在回答中被使用
- 排名靠前的文档权重更高

**公式**：
```
上下文精度 = Σ(Precision@k × relevance@k) / (相关文档数)
```

**目标**：0.80+

### 2.4 权限违规率

**定义**：搜索结果中包含未授权文档的比例

**评估方法**：
- 使用测试用户（不同权限级别）执行相同查询
- 验证每个用户的搜索结果中不出现未授权文档

**公式**：
```
权限违规率 = (未授权文档显示次数) / (总搜索次数)
```

**目标**：0%（零容忍）

### 2.5 响应延迟

| 百分位 | 目标（KB 模式） | 目标（Agent 模式） |
|--------|----------------|-------------------|
| P50 | < 3 秒 | < 8 秒 |
| P95 | < 8 秒 | < 20 秒 |
| P99 | < 15 秒 | < 30 秒 |

## 3. 权限控制指标

### 3.1 测试矩阵

| 测试用例 | 预期结果 | 验证方法 |
|----------|----------|----------|
| 管理员搜索机密文档 | 显示 | 确认 SID 匹配 |
| 普通用户搜索机密文档 | 不显示 | 确认 SID 不匹配 |
| 所有用户搜索 Everyone 文档 | 所有人可见 | 确认 S-1-1-0 匹配 |
| 无 SID 的用户搜索 | 拒绝所有（Fail-Closed） | 无 DynamoDB 记录时的行为 |
| 用户在组添加后立即搜索 | 新组文档显示 | 验证 AD Sync 后的行为 |
| 用户在组移除后立即搜索 | 旧组文档隐藏 | 验证缓存 TTL 后的行为 |

### 3.2 边缘情况测试

| 情况 | 预期行为 | 备注 |
|------|----------|------|
| Allow / Deny 冲突 | Deny 优先（本系统仅使用 Allow 列表） | NTFS ACL Deny ACE 设计上不反映在 `.metadata.json` 中 |
| 组嵌套 | 通过父组 SID 允许 | AD 嵌套组作为展开的 SID 列表管理 |
| 继承权限 vs 显式权限 | 两个 SID 都包含在 `.metadata.json` 中 | 枚举所有有效权限 SID |
| 重命名 / 移动后的权限 | 目标继承权限适用 | 需要重新生成 `.metadata.json` |
| 混合 SMB 和 NFS 访问 | 取决于安全样式 | NTFS 样式：SID，UNIX 样式：UID/GID |
| SID 无法解析的用户 | Fail-Closed（拒绝所有） | DynamoDB 中无 SID 数据 |
| 权限移除后立即搜索 | 在缓存 TTL 内可用旧权限搜索 | 最大 5 分钟延迟（紧急情况手动清除） |

## 4. Agent 评估指标

### 4.1 任务成功率

**定义**：Agent 正确完成任务的比例

**公式**：
```
任务成功率 = (正确完成的任务数) / (总任务数)
```

**目标**：80%+

### 4.2 工具调用准确率

**定义**：Agent 使用适当参数进行适当工具调用的比例

**评估项目**：
- 正确的工具选择
- 正确的参数设置
- 避免不必要的工具调用

**目标**：90%+

### 4.3 人工升级率

**定义**：Agent 将判断交给人工的比例

**公式**：
```
升级率 = (升级次数) / (总任务数)
```

**目标**：20% 以下（复杂任务可接受）

### 4.4 每任务成本

**公式**：
```
每任务成本 = (输入 token × 输入价格 + 输出 token × 输出价格) / 任务数
```

**预估**：
| 模型 | 输入价格 | 输出价格 | 平均任务成本 |
|------|----------|----------|-------------|
| Claude Haiku | $0.001/1K | $0.005/1K | $0.005–$0.02 |
| Claude Sonnet | $0.003/1K | $0.015/1K | $0.02–$0.10 |
| Claude Opus | $0.015/1K | $0.075/1K | $0.10–$0.50 |

## 模型选择 / 成本 / 延迟比较

### 向量存储选择

| 方面 | S3 Vectors | OpenSearch Serverless |
|------|-----------|---------------------|
| 月度成本（小规模） | $5–$20 | $700+ |
| 查询延迟 | 100ms–1s | 50ms–200ms |
| 推荐规模 | ~10,000 文档 | 10,000+ 文档 |
| 推荐用途 | PoC、小规模生产 | 高 QPS 生产 |

### 嵌入模型选择

| 模型 | 维度 | 多语言 | 成本 | 推荐用途 |
|------|------|--------|------|----------|
| Titan Embed Text v2 | 1024 | ✅ | $0.0001/1K tokens | 默认（成本高效） |
| Nova Multimodal | 1024 | ✅ | $0.0002/image | 多模态搜索 |

### 生成模型选择

| 模型 | 使用场景 | 输入成本 | 输出成本 | 延迟 |
|------|----------|----------|----------|------|
| Claude Haiku | 简单问题、Smart Routing: simple | $0.001/1K | $0.005/1K | ~2s |
| Claude Sonnet | 分析性问题、Smart Routing: complex | $0.003/1K | $0.015/1K | ~5s |
| Claude Opus | 大上下文、Smart Routing: full-context | $0.015/1K | $0.075/1K | ~10s |
