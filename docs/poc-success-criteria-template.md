### 2. PoC 目的と範囲

| 項目 | 内容 |
|------|------|
| **解決したい業務課題** | （例: 設計文書の検索に平均15分かかり、プロジェクト遅延の原因になっている） |
| **対象部門** | （例: 設計部門 + 品質管理部門、計30名） |
| **対象データ** | （例: 設計図面PDF 500件、技術仕様書 200件、品質レポート 100件） |
| **PoC期間** | （例: 4週間 — 2026/06/01 〜 2026/06/28） |
| **投入予算上限** | （例: AWS利用料 $2,000/月 以内） |

### 3. 成功指標（Go/No-Go 基準）

#### 必須達成指標（全て達成で Go）

| # | 指標 | 目標値 | 計測方法 | 達成/未達成 |
|---|------|--------|---------|-----------|
| 1 | 権限違反件数 | **0件** | 権限マトリクステスト + 手動検証 | ☐ |
| 2 | 回答精度（関連性スコア） | **3.5/5.0 以上** | 評価担当による10問以上の定性評価 | ☐ |
| 3 | 応答時間（P95） | **10秒以内** | CloudWatch メトリクス | ☐ |
| 4 | 可用性 | **99%以上**（PoC期間中） | CloudWatch アラーム | ☐ |

#### 望ましい達成指標（達成で加点）

| # | 指標 | 目標値 | 計測方法 | 達成/未達成 |
|---|------|--------|---------|-----------|
| 5 | 検索時間削減率 | 50%以上 | ユーザーアンケート（Before/After） | ☐ |
| 6 | 一次回答率 | 60%以上 | ユーザーフィードバック（👍/👎） | ☐ |
| 7 | ユーザー満足度 | 4.0/5.0以上 | PoC終了時アンケート | ☐ |
| 8 | Citation付き回答率 | 90%以上 | 自動集計 | ☐ |

---

### 4. Go/No-Go 判定基準

| 判定 | 条件 |
|------|------|
| **Go（次フェーズへ進む）** | 必須指標 #1〜#4 全て達成 + 望ましい指標 2つ以上達成 |
| **Conditional Go（条件付き）** | 必須指標 #1〜#4 全て達成 + 望ましい指標 1つ以下 → 改善計画を策定して再評価 |
| **No-Go（中止/再検討）** | 必須指標のいずれかが未達成 → 根本原因分析 → 再PoC or 方針変更 |

**判定日**: PoC期間終了後 5営業日以内  
**判定者**: ビジネススポンサー（上記ステークホルダー表の記載者）

---

### 5. 次フェーズの条件

Go判定後、本番移行（L2→L3）に進むための追加条件:

- [ ] セキュリティレビュー完了（[本番化チェックリスト](production-readiness-checklist.md) L2→L3セクション）
- [ ] 運用設計完了（SLO定義、アラーム設定、ランブック作成）
- [ ] コスト見積もり承認（[コスト見積もりワークシート](cost-estimation-worksheet.md)）
- [ ] データオーナーによる本番データ投入承認
- [ ] 監査ログ保全設計の承認

---

### 6. リスクと前提条件

| リスク | 影響 | 緩和策 |
|--------|------|--------|
| データ品質が低い（OCR精度、メタデータ不備） | 回答精度低下 | PoC前にサンプルデータで品質確認 |
| ユーザー参加率が低い | 評価データ不足 | キックオフで目的共有、週次フォローアップ |
| 権限設計が複雑すぎる | 設定工数増大 | 最小限の権限グループから開始 |
| モデルの回答品質が期待以下 | PoC失敗 | プロンプト調整、チャンキング戦略変更で対応 |

| 前提条件 | 確認状況 |
|---------|---------|
| AWS アカウント利用可能 | ☐ 確認済み |
| 対象データの提供可能 | ☐ 確認済み |
| 評価担当者のアサイン完了 | ☐ 確認済み |
| ネットワーク要件（VPN等）確認済み | ☐ 確認済み |
