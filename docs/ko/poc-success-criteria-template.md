### 2. PoC 목적과 범위

| 항목 | 내용 |
|------|------|
| **해결하려는 업무 과제** | (예: 설계 문서 검색에 평균 15분이 걸려 프로젝트 지연의 원인이 되고 있다) |
| **대상 부문** | (예: 설계 부문 + 품질 관리 부문, 총 30명) |
| **대상 데이터** | (예: 설계 도면 PDF 500건, 기술 사양서 200건, 품질 리포트 100건) |
| **PoC 기간** | (예: 4주간 — 2026/06/01 ~ 2026/06/28) |
| **투입 예산 상한** | (예: AWS 이용료 $2,000/월 이내) |

### 3. 성공 지표(Go/No-Go 기준)

#### 필수 달성 지표(전부 달성으로 Go)

| # | 지표 | 목표값 | 측정 방법 | 달성/미달성 |
|---|------|--------|---------|-----------|
| 1 | 권한 위반 건수 | **0건** | 권한 매트릭스 테스트 + 수동 검증 | ☐ |
| 2 | 답변 정확도(관련성 점수) | **3.5/5.0 이상** | 평가 담당자에 의한 10문항 이상의 정성 평가 | ☐ |
| 3 | 응답 시간(P95) | **10초 이내** | CloudWatch 메트릭 | ☐ |
| 4 | 가용성 | **99% 이상**(PoC 기간 중) | CloudWatch 알람 | ☐ |

#### 바람직한 달성 지표(달성 시 가점)

| # | 지표 | 목표값 | 측정 방법 | 달성/미달성 |
|---|------|--------|---------|-----------|
| 5 | 검색 시간 단축률 | 50% 이상 | 사용자 설문(Before/After) | ☐ |
| 6 | 최초 답변 해결률 | 60% 이상 | 사용자 피드백(👍/👎) | ☐ |
| 7 | 사용자 만족도 | 4.0/5.0 이상 | PoC 종료 시 설문 | ☐ |
| 8 | Citation 포함 답변률 | 90% 이상 | 자동 집계 | ☐ |

### 4. Go/No-Go 판정 기준

| 판정 | 조건 |
|------|------|
| **Go(다음 단계로 진행)** | 필수 지표 #1~#4 전부 달성 + 바람직한 지표 2개 이상 달성 |
| **Conditional Go(조건부)** | 필수 지표 #1~#4 전부 달성 + 바람직한 지표 1개 이하 → 개선 계획을 수립하여 재평가 |
| **No-Go(중지/재검토)** | 필수 지표 중 하나라도 미달성 → 근본 원인 분석 → 재PoC 또는 방침 변경 |

**판정일**: PoC 기간 종료 후 5영업일 이내  
**판정자**: 비즈니스 스폰서(위 이해관계자 표의 기재자)

---

### 5. 다음 단계의 조건

Go 판정 후, 프로덕션 전환(L2→L3)으로 진행하기 위한 추가 조건:

- [ ] 보안 리뷰 완료([프로덕션 준비 체크리스트](production-readiness-checklist.md) L2→L3 섹션)
- [ ] 운영 설계 완료(SLO 정의, 알람 설정, 런북 작성)
- [ ] 비용 견적 승인([비용 견적 워크시트](cost-estimation-worksheet.md))
- [ ] 데이터 오너에 의한 프로덕션 데이터 투입 승인
- [ ] 감사 로그 보전 설계 승인

### 6. 리스크와 전제 조건

| 리스크 | 영향 | 완화책 |
|--------|------|--------|
| 데이터 품질이 낮음(OCR 정확도, 메타데이터 미비) | 답변 정확도 저하 | PoC 전에 샘플 데이터로 품질 확인 |
| 사용자 참여율이 낮음 | 평가 데이터 부족 | 킥오프에서 목적 공유, 주간 팔로업 |
| 권한 설계가 너무 복잡함 | 설정 공수 증대 | 최소한의 권한 그룹부터 시작 |
| 모델의 답변 품질이 기대 이하 | PoC 실패 | 프롬프트 조정, 청킹 전략 변경으로 대응 |

| 전제 조건 | 확인 상황 |
|---------|---------|
| AWS 계정 이용 가능 | ☐ 확인 완료 |
| 대상 데이터 제공 가능 | ☐ 확인 완료 |
| 평가 담당자 배정 완료 | ☐ 확인 완료 |
| 네트워크 요건(VPN 등) 확인 완료 | ☐ 확인 완료 |
