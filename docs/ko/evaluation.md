## 1. 비즈니스 KPI

### 정의 및 측정 방법

| KPI | 정의 | 목표 (PoC) | 측정 방법 |
|-----|------|-----------|-----------|
| 검색 시간 단축률 | 기존 수동 검색 대비 시간 절감 | 50%+ | 사용자 설문 + 타임스탬프 비교 |
| 1차 해결률 | AI 답변만으로 해결된 비율 | 60%+ | 사용자 피드백 (👍/👎) |
| 문의 감소율 | 헬프데스크 문의 감소량 | 30%+ | Before/After 티켓 수 비교 |
| 인용률 | 인용이 포함된 답변 비율 | 90%+ | 자동 인용 유무 집계 |
| 권한 위반 건수 | 비인가 문서 표시 건수 | 0 | 권한 매트릭스 테스트 + 감사 로그 |
| 월간 활성 사용자율 | 등록 사용자 중 월간 사용률 | 70%+ | Cognito + 접근 로그 |

### 측정 대시보드

CloudWatch 대시보드(`enableMonitoring=true`)에서 다음을 시각화합니다:

- 일간/주간 검색 요청 수
- 사용자별 사용 빈도
- 답변 생성 성공률
- 평균 응답 시간 (P50/P95/P99)
- Guardrails 개입률

## 2. RAG 품질 지표

### 2.1 답변 관련성

**정의**: 생성된 답변이 사용자의 질문에 얼마나 관련이 있는지

**평가 방법**:
- 인간 평가: 5점 척도 (1: 무관 – 5: 완전히 관련)
- 자동 평가: LLM-as-Judge (Claude에 의한 자동 채점)

**목표**: 평균 4.0+ (5점 척도)

### 2.2 충실도 (Faithfulness)

**정의**: 생성된 답변이 검색된 문서의 내용에 충실한지 (환각 없음)

**평가 방법**:
- 답변의 각 주장을 인용 문서와 대조
- 지원되지 않는 주장의 비율 측정

**공식**:
```
Faithfulness = (지원되는 주장 수) / (답변의 총 주장 수)
```

**목표**: 0.90+

### 2.3 컨텍스트 정밀도

**정의**: 검색된 문서 중 실제로 답변 생성에 기여한 비율

**평가 방법**:
- 검색 결과의 각 문서가 답변에 사용되었는지 판단
- 상위 순위 문서에 더 높은 가중치 부여

**공식**:
```
Context Precision = Σ(Precision@k × relevance@k) / (관련 문서 수)
```

**목표**: 0.80+

### 2.4 권한 위반율

**정의**: 비인가 문서가 포함된 검색 결과의 비율

**평가 방법**:
- 테스트 사용자(다른 권한 수준)로 동일 쿼리 실행
- 각 사용자의 검색 결과에 비인가 문서가 나타나지 않는지 확인

**공식**:
```
Permission Violation Rate = (비인가 문서 표시 수) / (총 검색 수)
```

**목표**: 0% (제로 톨러런스)

### 2.5 응답 지연 시간

| 백분위 | 목표 (KB 모드) | 목표 (Agent 모드) |
|--------|---------------|------------------|
| P50 | < 3초 | < 8초 |
| P95 | < 8초 | < 20초 |
| P99 | < 15초 | < 30초 |

## 3. 권한 제어 지표

### 3.1 테스트 매트릭스

| 테스트 케이스 | 예상 결과 | 검증 방법 |
|--------------|-----------|-----------|
| 관리자가 기밀 문서 검색 | 표시됨 | SID 매칭 확인 |
| 일반 사용자가 기밀 문서 검색 | 표시되지 않음 | SID 불일치 확인 |
| 모든 사용자가 Everyone 문서 검색 | 모두에게 표시 | S-1-1-0 매칭 확인 |
| SID 없는 사용자가 검색 | 모두 거부 (Fail-Closed) | DynamoDB 레코드 없을 때 동작 |
| 그룹 추가 직후 사용자 검색 | 새 그룹 문서 표시 | AD Sync 후 동작 확인 |
| 그룹 제거 직후 사용자 검색 | 이전 그룹 문서 숨김 | 캐시 TTL 후 동작 확인 |

### 3.2 엣지 케이스 테스트

| 케이스 | 예상 동작 | 비고 |
|--------|-----------|------|
| Allow / Deny 충돌 | Deny 우선 (본 시스템은 Allow 목록만 사용) | NTFS ACL Deny ACE는 설계상 `.metadata.json`에 반영되지 않음 |
| 그룹 중첩 | 상위 그룹 SID로 허용 | AD 중첩 그룹은 확장된 SID 목록으로 관리 |
| 상속 vs 명시적 권한 | 두 SID 모두 `.metadata.json`에 포함 | 모든 유효 권한 SID 열거 |
| Rename / Move 후 권한 | 대상 위치의 상속 권한 적용 | `.metadata.json` 재생성 필요 |
| SMB와 NFS 혼합 접근 | 보안 스타일에 따라 다름 | NTFS 스타일: SID, UNIX 스타일: UID/GID |
| 해석 불가능한 SID를 가진 사용자 | Fail-Closed (모두 거부) | DynamoDB에 SID 데이터 없음 |
| 권한 제거 직후 검색 | 캐시 TTL 내 이전 권한으로 검색 가능 | 최대 5분 지연 (긴급 시 수동 삭제) |

## 4. Agent 평가 지표

### 4.1 태스크 성공률

**정의**: Agent가 올바르게 완료한 태스크의 비율

**공식**:
```
Task Success Rate = (올바르게 완료된 태스크) / (총 태스크)
```

**목표**: 80%+

### 4.2 도구 호출 정확도

**정의**: Agent가 적절한 도구를 적절한 매개변수로 호출한 비율

**평가 항목**:
- 올바른 도구 선택
- 올바른 매개변수 설정
- 불필요한 도구 호출 회피

**목표**: 90%+

### 4.3 인간 에스컬레이션율

**정의**: Agent가 인간에게 판단을 위임한 비율

**공식**:
```
Escalation Rate = (에스컬레이션 수) / (총 태스크)
```

**목표**: 20% 이하 (복잡한 태스크에서는 허용)

### 4.4 태스크당 비용

**공식**:
```
Cost per Task = (입력 토큰 × 입력 가격 + 출력 토큰 × 출력 가격) / 태스크 수
```

**추정**:
| 모델 | 입력 가격 | 출력 가격 | 평균 태스크 비용 |
|------|----------|----------|-----------------|
| Claude Haiku | $0.001/1K | $0.005/1K | $0.005–$0.02 |
| Claude Sonnet | $0.003/1K | $0.015/1K | $0.02–$0.10 |
| Claude Opus | $0.015/1K | $0.075/1K | $0.10–$0.50 |
