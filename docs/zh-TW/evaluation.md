## 1. 商業 KPI

### 定義與測量方法

| KPI | 定義 | 目標（PoC） | 測量方法 |
|-----|------|-------------|----------|
| 搜尋時間縮短率 | 與傳統手動搜尋相比的時間節省 | 50%+ | 使用者問卷 + 時間戳比較 |
| 首次解決率 | 僅靠 AI 回答即可解決的比例 | 60%+ | 使用者回饋（👍/👎） |
| 諮詢減少率 | 服務台諮詢的減少量 | 30%+ | 導入前後工單數量比較 |
| 引用率 | 附帶引用的回答比例 | 90%+ | 自動引用存在彙總 |
| 權限違規次數 | 顯示未授權文件的次數 | 0 | 權限矩陣測試 + 稽核日誌 |
| 月活躍使用者率 | 註冊使用者中的月使用率 | 70%+ | Cognito + 存取日誌 |

### 測量儀表板

在 CloudWatch 儀表板（`enableMonitoring=true`）上視覺化以下項目：

- 每日/每週搜尋請求數
- 每使用者使用頻率
- 回答產生成功率
- 平均回應時間（P50/P95/P99）
- Guardrails 介入率

## 2. RAG 品質指標

### 2.1 回答相關性

**定義**：產生的回答與使用者問題的相關程度

**評估方法**：
- 人工評估：5 分量表（1：不相關 – 5：完全相關）
- 自動評估：LLM-as-Judge（由 Claude 自動評分）

**目標**：平均 4.0+（5 分量表）

### 2.2 忠實度

**定義**：產生的回答是否忠實於檢索文件的內容（無幻覺）

**評估方法**：
- 將回答中的每個主張與引用文件交叉比對
- 測量無支持主張的比例

**公式**：
```
忠實度 = (有支持的主張數) / (回答中的總主張數)
```

**目標**：0.90+

### 2.3 上下文精確度

**定義**：檢索文件中實際對回答產生有貢獻的比例

**評估方法**：
- 判斷搜尋結果中的每個文件是否被用於回答
- 排名較高的文件權重較大

**公式**：
```
上下文精確度 = Σ(Precision@k × relevance@k) / (相關文件數)
```

**目標**：0.80+

### 2.4 權限違規率

**定義**：搜尋結果中包含未授權文件的比例

**評估方法**：
- 使用測試使用者（不同權限等級）執行相同查詢
- 驗證每個使用者的搜尋結果中不會出現未授權文件

**公式**：
```
權限違規率 = (未授權文件顯示次數) / (總搜尋次數)
```

**目標**：0%（零容忍）

### 2.5 回應延遲

| 百分位 | 目標（KB 模式） | 目標（Agent 模式） |
|--------|----------------|-------------------|
| P50 | < 3 秒 | < 8 秒 |
| P95 | < 8 秒 | < 20 秒 |
| P99 | < 15 秒 | < 30 秒 |

## 3. 權限控制指標

### 3.1 測試矩陣

| 測試案例 | 預期結果 | 驗證方法 |
|----------|----------|----------|
| 管理員搜尋機密文件 | 顯示 | 確認 SID 匹配 |
| 一般使用者搜尋機密文件 | 不顯示 | 確認 SID 不匹配 |
| 所有使用者搜尋 Everyone 文件 | 全部顯示 | 確認 S-1-1-0 匹配 |
| 無 SID 的使用者搜尋 | 拒絕所有（Fail-Closed） | 無 DynamoDB 記錄時的行為 |
| 群組新增後立即搜尋 | 顯示新群組文件 | 驗證 AD Sync 後的行為 |
| 群組移除後立即搜尋 | 隱藏舊群組文件 | 驗證快取 TTL 後的行為 |

### 3.2 邊界案例測試

| 案例 | 預期行為 | 備註 |
|------|----------|------|
| Allow / Deny 衝突 | Deny 優先（本系統僅使用 Allow 清單） | NTFS ACL Deny ACE 設計上不反映於 `.metadata.json` |
| 群組巢狀 | 由父群組 SID 允許 | AD 巢狀群組作為展開的 SID 清單管理 |
| 繼承 vs 明確權限 | 兩者的 SID 都包含在 `.metadata.json` 中 | 列舉所有有效權限 SID |
| Rename / Move 後的權限 | 套用目的地繼承權限 | 需要重新產生 `.metadata.json` |
| 混合 SMB 和 NFS 存取 | 取決於安全樣式 | NTFS 樣式：SID、UNIX 樣式：UID/GID |
| 無法解析 SID 的使用者 | Fail-Closed（拒絕所有） | DynamoDB 中無 SID 資料 |
| 權限移除後立即搜尋 | 在快取 TTL 內以舊權限可搜尋 | 最大 5 分鐘延遲（緊急時手動清除） |

## 4. Agent 評估指標

### 4.1 任務成功率

**定義**：Agent 正確完成的任務比例

**公式**：
```
任務成功率 = (正確完成的任務數) / (總任務數)
```

**目標**：80%+

### 4.2 工具呼叫準確度

**定義**：Agent 以適當參數進行適當工具呼叫的比例

**評估項目**：
- 正確的工具選擇
- 正確的參數設定
- 避免不必要的工具呼叫

**目標**：90%+

### 4.3 人工升級率

**定義**：Agent 將判斷交由人工處理的比例

**公式**：
```
升級率 = (升級次數) / (總任務數)
```

**目標**：20% 以下（複雜任務可接受）

### 4.4 每任務成本

**公式**：
```
每任務成本 = (輸入 token × 輸入價格 + 輸出 token × 輸出價格) / 任務數
```

**預估**：
| 模型 | 輸入價格 | 輸出價格 | 平均任務成本 |
|------|----------|----------|-------------|
| Claude Haiku | $0.001/1K | $0.005/1K | $0.005–$0.02 |
| Claude Sonnet | $0.003/1K | $0.015/1K | $0.02–$0.10 |
| Claude Opus | $0.015/1K | $0.075/1K | $0.10–$0.50 |

## 模型選擇 / 成本 / 延遲比較

### 向量儲存選擇

| 面向 | S3 Vectors | OpenSearch Serverless |
|------|-----------|---------------------|
| 每月成本（小規模） | $5–$20 | $700+ |
| 查詢延遲 | 100ms–1s | 50ms–200ms |
| 建議規模 | ~10,000 文件 | 10,000+ 文件 |
| 建議用途 | PoC、小規模生產 | 高 QPS 生產 |

### 嵌入模型選擇

| 模型 | 維度 | 多語言 | 成本 | 建議用途 |
|------|------|--------|------|----------|
| Titan Embed Text v2 | 1024 | ✅ | $0.0001/1K tokens | 預設（成本效率） |
| Nova Multimodal | 1024 | ✅ | $0.0002/image | 多模態搜尋 |

### 生成模型選擇

| 模型 | 使用案例 | 輸入成本 | 輸出成本 | 延遲 |
|------|----------|----------|----------|------|
| Claude Haiku | 簡單問題、Smart Routing: simple | $0.001/1K | $0.005/1K | ~2s |
| Claude Sonnet | 分析性問題、Smart Routing: complex | $0.003/1K | $0.015/1K | ~5s |
| Claude Opus | 大上下文、Smart Routing: full-context | $0.015/1K | $0.075/1K | ~10s |
