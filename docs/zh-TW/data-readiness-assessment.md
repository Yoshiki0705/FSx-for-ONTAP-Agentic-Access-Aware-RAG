# 資料就緒度評估範本

**🌐 Language:** [日本語](../data-readiness-assessment.md) | [English](../en/data-readiness-assessment.md) | [한국어](../ko/data-readiness-assessment.md) | [简体中文](../zh-CN/data-readiness-assessment.md) | **繁體中文** | [Français](../fr/data-readiness-assessment.md) | [Deutsch](../de/data-readiness-assessment.md) | [Español](../es/data-readiness-assessment.md)

**建立日期**: 2026-05-24  
**對象**: 用於在 PoC 啟動前評估資料準備狀況的範本

---

## 概述

本範本協助評估將要匯入 Permission-aware RAG 系統的資料準備狀況，支援安全且有效的 PoC 實施。請由資料擁有者與技術負責人共同填寫。

---

## 1. 資料所在確認

| # | 確認項目 | 回答 |
|---|---------|------|
| 1.1 | 資料的實體儲存位置為？ | ☐ 地端檔案伺服器 ☐ AWS上（S3/EFS/FSx） ☐ SaaS ☐ 其他: ________ |
| 1.2 | 資料量（檔案數 / 總容量） | 檔案數: ________ 個，總容量: ________ GB |
| 1.3 | 檔案格式構成 | PDF: ___% / DOCX: ___% / TXT: ___% / 其他: ___% |
| 1.4 | 資料更新頻率 | ☐ 每日 ☐ 每週 ☐ 每月 ☐ 不定期 ☐ 靜態（無更新） |
| 1.5 | 資料語言 | ☐ 日語 ☐ 英語 ☐ 混合 ☐ 其他: ________ |

## 2. 資料分類

| 機密等級 | 定義 | 對應檔案數 | 範例 |
|-----------|------|-------------|-----|
| **公開** | 可對外公開 | ________ 個 | 產品型錄、新聞稿 |
| **內部限定** | 全體員工可存取 | ________ 個 | 內部規程、福利資訊 |
| **部門限定** | 僅特定部門 | ________ 個 | 專案計畫、技術規格 |
| **機密** | 僅特定職位 | ________ 個 | 財務報告、人事資訊 |
| **絕密** | 僅指定人員 | ________ 個 | M&A 資料、法律訴訟文件 |

## 3. 權限結構確認

| # | 確認項目 | 回答 |
|---|---------|------|
| 3.1 | 目前的權限管理方式為？ | ☐ NTFS ACL (Active Directory) ☐ UNIX 權限 ☐ 應用程式專有 ☐ 無（所有人可存取） |
| 3.2 | 權限群組數量 | ________ 個群組 |
| 3.3 | 權限的階層結構 | ☐ 扁平 ☐ 2層 ☐ 3層以上 ☐ 不明 |
| 3.4 | 權限變更頻率 | ☐ 每日 ☐ 每週 ☐ 每月 ☐ 每季 ☐ 幾乎沒有 |
| 3.5 | 是否對權限的準確性有信心 | ☐ 高 ☐ 中等 ☐ 低（需要盤點） |

---

## 4. 資料品質確認

| # | 確認項目 | 回答 | 影響 |
|---|---------|------|------|
| 4.1 | 是否有需要 OCR 的掃描 PDF | ☐ 無 ☐ 部分 ☐ 大部分 | 影響 RAG 精度 |
| 4.2 | 檔案名稱是否反映內容 | ☐ 是 ☐ 部分 ☐ 否 | 影響檢索精度 |
| 4.3 | 資料夾結構是否經過邏輯整理 | ☐ 是 ☐ 部分 ☐ 否 | 影響權限設計 |
| 4.4 | 是否存在重複檔案 | ☐ 無 ☐ 少量 ☐ 大量 | 影響儲存成本 |
| 4.5 | 是否混入了過時/無效的檔案 | ☐ 無 ☐ 少量 ☐ 大量 | 影響回答精度 |

---

## 5. 合規·隱私確認

| # | 確認項目 | 回答 | 因應 |
|---|---------|------|------|
| 5.1 | 是否包含個人資訊（PII） | ☐ 無 ☐ 有 → 種類: ________ | 遮罩 or Guardrails PII 偵測 |
| 5.2 | 是否為受監管資料 | ☐ 無 ☐ 有 → 監管: ________ | 必須進行法務確認 |
| 5.3 | 是否存在資料出境限制 | ☐ 無 ☐ 有 | 影響區域選擇 |
| 5.4 | 是否有資料保留期限要求 | ☐ 無 ☐ 有 → 期限: ________ | 影響備份設計 |
| 5.5 | 是否有稽核軌跡保全要求 | ☐ 無 ☐ 有 | 必須 `enableMonitoring=true` |

## 7. 就緒度判定

根據所有章節的回答，進行以下判定：

| 判定 | 條件 |
|------|------|
| **Ready** | 第 1-6 章節全部回答完畢，已完成 PII 因應，已取得資料擁有者核准 |
| **Conditional** | 部分未回答，但可使用示範資料啟動 → 並行準備資料 |
| **Not Ready** | 資料所在不明、權限結構不明、PII 未確認 → 需先進行資料整備階段 |
