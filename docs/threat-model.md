## 概要

本ドキュメントは、Permission-aware Agentic RAG システムに対する主要な脅威、攻撃経路、影響、既存の緩和策、および推奨される追加対策を整理した脅威モデルです。

> **⚠️ スコープと制限事項**: 本脅威モデルはリファレンスアーキテクチャに対する参考情報です。顧客環境での正式な脅威モデリング演習を代替するものではありません。実際のデプロイメントでは、組織のセキュリティチームによる環境固有の脅威分析を実施してください。

## システム境界と信頼境界

```
┌─────────────────────────────────────────────────────────────────────────┐
│ 信頼境界 1: インターネット → CloudFront                                   │
│  攻撃者: 外部ユーザー、ボット、スクリプト                                  │
├─────────────────────────────────────────────────────────────────────────┤
│ 信頼境界 2: CloudFront → Lambda (WebApp)                                │
│  攻撃者: 認証済みだが権限外のユーザー                                     │
├─────────────────────────────────────────────────────────────────────────┤
│ 信頼境界 3: Lambda → Bedrock / DynamoDB / FSx                           │
│  攻撃者: 内部脅威、設定ミス、サプライチェーン                              │
├─────────────────────────────────────────────────────────────────────────┤
│ 信頼境界 4: FSx ONTAP → S3 Access Point → Bedrock KB                    │
│  攻撃者: 権限昇格、メタデータ改ざん                                       │
└─────────────────────────────────────────────────────────────────────────┘
```

## 脅威カタログ

### T1: Prompt Injection

| 項目 | 内容 |
|------|------|
| **脅威** | 悪意あるプロンプトにより、システムプロンプトの無視、権限チェックのバイパス、意図しない情報開示を引き起こす |
| **攻撃経路** | ユーザー入力 → Converse API / Agent |
| **影響** | 高 — 権限外ドキュメントの内容漏えい、システム動作の改変 |
| **既存の緩和策** | Bedrock Guardrails（コンテンツフィルタ）、SID フィルタリングはアプリ側で実施（LLM がバイパス不可） |
| **追加推奨** | Guardrails の Prompt Attack フィルタ有効化、入力長制限、出力検証レイヤー追加 |
| **残存リスク** | 間接的 Prompt Injection（ドキュメント内に埋め込まれた指示）は完全には防げない |

**重要**: 本システムでは SID フィルタリングが LLM の外側（アプリケーションレイヤー）で実行されるため、Prompt Injection で権限チェック自体をバイパスすることはできません。ただし、許可されたドキュメント内の情報を意図しない形で開示させるリスクは残ります。

---

### T2: Retrieval Poisoning

| 項目 | 内容 |
|------|------|
| **脅威** | 悪意あるドキュメントを FSx ボリュームに配置し、RAG 検索結果を汚染する |
| **攻撃経路** | CIFS/SMB アクセス → FSx ボリューム → S3 AP → Bedrock KB |
| **影響** | 中〜高 — 誤情報の生成、フィッシング誘導、間接的 Prompt Injection |
| **既存の緩和策** | NTFS ACL による書き込み制限、Transfer Family の IAM ロール制限、`.metadata.json` はサービスロールのみ生成可能 |
| **追加推奨** | ドキュメント投入時のマルウェアスキャン、コンテンツ検証パイプライン、異常検出（急激なドキュメント増加アラート） |
| **残存リスク** | 正規の書き込み権限を持つ内部ユーザーによる意図的な汚染 |

---

### T3: Cross-User Data Leakage

| 項目 | 内容 |
|------|------|
| **脅威** | ユーザー A の検索結果にユーザー B のみがアクセス可能なドキュメントが含まれる |
| **攻撃経路** | SID フィルタリングの実装バグ、キャッシュ汚染、セッション混同 |
| **影響** | 高 — 機密情報の漏えい、コンプライアンス違反 |
| **既存の緩和策** | SID マッチング（集合の積）、Fail-Closed 原則、権限マトリクステスト（31 シナリオ） |
| **追加推奨** | 定期的な権限マトリクステストの自動実行、異常検出（通常アクセスしないドキュメントへのアクセスパターン） |
| **残存リスク** | 低 — SID フィルタリングは LLM の外側で実行されるため、実装バグ以外でのバイパスは困難 |

---

### T4: Stale ACL / Permission Drift

| 項目 | 内容 |
|------|------|
| **脅威** | ファイル ACL が変更されたが、ベクトルストアのメタデータや権限キャッシュに古い権限が残存する |
| **攻撃経路** | ACL 変更 → メタデータ未更新 → 旧権限で検索可能 |
| **影響** | 中 — 権限剥奪後も一定期間アクセス可能（最大 35 分） |
| **既存の緩和策** | KB Auto-Sync（15 分間隔）、権限キャッシュ TTL（5 分）、緊急権限剥奪手順 |
| **追加推奨** | ACL 変更イベントの即時検出（FSx Audit Log → EventBridge）、キャッシュ TTL の短縮検討、権限変更監査ログ |
| **残存リスク** | Eventually Consistent モデルのため、完全なリアルタイム反映は不可能。緊急時は手動剥奪で対応 |

**詳細**: [permission-consistency.md](permission-consistency.md) を参照

---

### T5: Over-Permissive Cache

| 項目 | 内容 |
|------|------|
| **脅威** | 権限キャッシュが過剰に許可的な状態で固定され、本来拒否すべきアクセスを許可し続ける |
| **攻撃経路** | キャッシュ書き込み時の競合状態、TTL 設定ミス、キャッシュキー衝突 |
| **影響** | 高 — 権限外ドキュメントへの継続的アクセス |
| **既存の緩和策** | DynamoDB TTL による自動期限切れ（5 分）、キャッシュキーにユーザー ID + ドキュメント ID を含む |
| **追加推奨** | キャッシュヒット率の監視、異常に高いヒット率のアラート、定期的なキャッシュ全クリア（日次） |
| **残存リスク** | 低 — TTL が短いため、仮に汚染されても 5 分で自動回復 |

---

### T6: Agent Tool Abuse

| 項目 | 内容 |
|------|------|
| **脅威** | Agent が意図しないツールを呼び出し、データの変更・削除・外部送信を行う |
| **攻撃経路** | Prompt Injection → Agent の行動計画改変 → 危険なツール呼び出し |
| **影響** | 高 — データ破壊、情報漏えい、コスト爆発 |
| **既存の緩和策** | AgentCore Policy（ツールアクセス制限）、Action Group の IAM ロール最小権限化、読み取り専用ツールのみデフォルト提供 |
| **追加推奨** | Human Approval（外部アクション実行前の承認）、ツール呼び出し回数制限、コスト上限設定 |
| **残存リスク** | 中 — Agent の自律性と安全性のトレードオフ。読み取り専用に制限すればリスクは低い |

---

### T7: Audit Log Tampering

| 項目 | 内容 |
|------|------|
| **脅威** | 監査ログの改ざん・削除により、不正アクセスの証跡を隠蔽する |
| **攻撃経路** | Lambda 実行ロールの権限昇格 → CloudWatch Logs / S3 の改ざん |
| **影響** | 高 — インシデント調査不能、コンプライアンス違反 |
| **既存の緩和策** | CloudWatch Logs の保持ポリシー、IAM 最小権限 |
| **追加推奨** | S3 Object Lock（WORM）、CloudTrail ログの別アカウント保存、ログ整合性検証（CloudTrail Digest） |
| **残存リスク** | 低 — S3 Object Lock + 別アカウント保存で実質的に改ざん不可能 |

**詳細**: [governance-and-audit.md](governance-and-audit.md) を参照

---

### T8: Misconfigured Identity Federation

| 項目 | 内容 |
|------|------|
| **脅威** | OIDC / SAML / LDAP の設定ミスにより、不正なユーザーが認証を通過する、または正規ユーザーに過剰な権限が付与される |
| **攻撃経路** | IdP 設定ミス → 不正トークン発行 → Cognito 認証通過 → 過剰な SID 付与 |
| **影響** | 高 — 権限昇格、全ドキュメントへのアクセス |
| **既存の緩和策** | `authFailureMode=fail-closed`（権限取得失敗時のブロック）、Cognito トークン検証、LDAP ヘルスチェック |
| **追加推奨** | IdP 設定の定期監査、フェデレーションメタデータの自動検証、異常なグループ SID 数のアラート |
| **残存リスク** | 中 — IdP 側の設定は本システムの制御外。Fail-Closed で影響を限定 |

---

### T9: Vector Metadata Leakage

| 項目 | 内容 |
|------|------|
| **脅威** | ベクトルストアのメタデータ（SID 情報、ファイルパス）が意図せず露出し、組織構造やアクセス権限の情報が漏えいする |
| **攻撃経路** | S3 Vectors / OpenSearch Serverless への直接アクセス、API レスポンスの過剰な情報返却 |
| **影響** | 中 — 組織構造の推測、標的型攻撃の情報収集 |
| **既存の緩和策** | VPC エンドポイント経由のアクセス制限、IAM ポリシーによる直接アクセス防止、API レスポンスからの SID 情報除外（フロントエンド） |
| **追加推奨** | S3 Vectors バケットポリシーの最小権限化、OpenSearch Serverless のデータアクセスポリシー監査、メタデータの暗号化 |
| **残存リスク** | 低 — Bedrock KB 経由のアクセスのみ許可し、直接アクセスを IAM で防止 |

---

### T10: Denial of Wallet / Cost Abuse

| 項目 | 内容 |
|------|------|
| **脅威** | 大量のリクエストや高コストモデルの意図的な利用により、AWS 利用料金を爆発させる |
| **攻撃経路** | 認証済みユーザーによる大量クエリ、Agent モードでの無限ループ、高コストモデルの連続利用 |
| **影響** | 高 — 予期しない高額請求 |
| **既存の緩和策** | WAF レートリミット（2000 req/5min）、Smart Routing（低コストモデル優先）、Lambda 同時実行数制限 |
| **追加推奨** | AWS Budgets アラート、ユーザー別の日次クエリ上限、Agent ステップ数上限、Bedrock Provisioned Throughput の検討 |
| **残存リスク** | 中 — レートリミットで緩和されるが、正規ユーザーによる過剰利用は完全には防げない |

## 推奨される追加対策（優先順）

### 即時対応（P1）

1. **Guardrails Prompt Attack フィルタの有効化** — T1 対策
2. **Agent ツール呼び出しの Human Approval 実装** — T6 対策
3. **IdP 設定の定期監査プロセス確立** — T8 対策
4. **権限マトリクステストの CI/CD 組み込み** — T3 対策

### 短期対応（P2）

5. **S3 Object Lock による監査ログ保護** — T7 対策
6. **ACL 変更イベントの即時検出** — T4 対策
7. **ドキュメント投入時のコンテンツ検証** — T2 対策
8. **AWS Budgets + ユーザー別クエリ上限** — T10 対策

### 中期対応（P3）

9. **キャッシュヒット率の異常検出** — T5 対策
10. **ベクトルストアメタデータの暗号化** — T9 対策
