## 1. Smart Routing Verification

### Test Procedure

1. Access the CloudFront URL and sign in as the admin user
2. Enable **Smart Routing** in chat settings
3. Send the following 3 types of queries and verify the routing results

### Test Queries and Expected Results

| Query | Expected Tier | Expected Model | Verification Point |
|-------|--------------|---------------|-------------------|
| "Hello" | Simple | Haiku 4.5 | Response metadata contains `routingTier: simple` |
| "Please summarize the product catalog" | Complex | Sonnet 3.5 v2 | Response metadata contains `routingTier: complex` |
| "Analyze quarterly reports across all departments and identify cost reduction opportunities" | Full-context | Opus 4 | Response metadata contains `routingTier: full-context` |

### CloudWatch Metrics Verification

```bash
# Check routing distribution (past 1 hour)
aws cloudwatch get-metric-statistics \
  --namespace SmartRouting \
  --metric-name RoutingCount \
  --dimensions Name=RoutingTier,Value=simple \
  --start-time $(date -u -v-1H +%Y-%m-%dT%H:%M:%S) \
  --end-time $(date -u +%Y-%m-%dT%H:%M:%S) \
  --period 300 \
  --statistics Sum \
  --region ap-northeast-1
```

### Expected CloudWatch Logs Output

```json
{
  "level": "INFO",
  "message": "Smart routing decision",
  "query": "Hello",
  "classification": "simple",
  "confidence": 0.95,
  "selectedModel": "anthropic.claude-haiku-4-5-20251001-v1:0",
  "queryWordCount": 1,
  "hasAnalyticalTerms": false
}
```

## 2. Transfer Family IAM Deny Verification

### Test Procedure

Verify that partner users cannot overwrite `.metadata.json` files.

```bash
# 1. SFTP connection
sftp -i /path/to/partner-key \
  -o HostKeyAlgorithms=rsa-sha2-256,rsa-sha2-512 \
  partner-a@s-XXXXXXXXXXXXXXXXX.server.transfer.ap-northeast-1.amazonaws.com

# 2. Normal file upload (should succeed)
sftp> put test-document.pdf /uploads/partner-a/test-document.pdf

# 3. Attempt to overwrite .metadata.json (should be denied)
sftp> put fake-metadata.json /uploads/partner-a/test-document.pdf.metadata.json
```

### Expected Results

```
# Normal file: Success
Uploading test-document.pdf to /uploads/partner-a/test-document.pdf
test-document.pdf                                    100%  1234     12.3KB/s   00:00

# .metadata.json: Access Denied
Uploading fake-metadata.json to /uploads/partner-a/test-document.pdf.metadata.json
remote open("/uploads/partner-a/test-document.pdf.metadata.json"): Permission denied
```

### CloudTrail Verification

```bash
# Check Access Denied events
aws cloudtrail lookup-events \
  --lookup-attributes AttributeKey=EventName,AttributeValue=PutObject \
  --start-time $(date -u -v-1H +%Y-%m-%dT%H:%M:%S) \
  --region ap-northeast-1 \
  --query 'Events[?contains(CloudTrailEvent, `AccessDenied`)].{Time:EventTime,User:Username}'
```

### Screenshot Capture Points

- [ ] SFTP terminal showing successful normal file upload
- [ ] SFTP terminal showing `.metadata.json` upload denied
- [ ] CloudTrail Access Denied event

## 3. KB Auto-Sync Verification

### Test Procedure

1. Add a test file to the S3 Access Point
2. Verify that a scan executes within 5 minutes
3. Verify that an ingestion job starts and completes

```bash
# 1. Add a test file to S3 AP
aws s3api put-object \
  --bucket arn:aws:s3:ap-northeast-1:ACCOUNT:accesspoint/AP_NAME \
  --key test-auto-sync/new-document.md \
  --body ./test-document.md \
  --region ap-northeast-1

# 2. Add the corresponding .metadata.json
aws s3api put-object \
  --bucket arn:aws:s3:ap-northeast-1:ACCOUNT:accesspoint/AP_NAME \
  --key test-auto-sync/new-document.md.metadata.json \
  --body ./test-metadata.json \
  --region ap-northeast-1

# 3. Monitor Lambda logs (scan should execute within 5 minutes)
aws logs tail /aws/lambda/${PREFIX}-kb-auto-sync \
  --follow --region ap-northeast-1
```

### Expected Lambda Log Output

## 4. Capacity Guardrails Verification

### Test Procedure

Execute the same action in rapid succession to verify that rate limiting is triggered.

```bash
# Invoke the Guardrails Lambda directly (for testing)
for i in 1 2 3 4; do
  echo "=== Attempt $i ==="
  aws lambda invoke \
    --function-name ${PREFIX}-capacity-monitor \
    --payload '{"action": "volume_resize", "volume_id": "vol-test", "new_size_gb": 100}' \
    --region ap-northeast-1 \
    /tmp/guardrail-response-$i.json
  cat /tmp/guardrail-response-$i.json
  echo ""
  sleep 2
done
```

### Expected Results

```
=== Attempt 1 ===
{"decision": "ALLOWED", "reason": "All checks passed", "action_count": 1}

=== Attempt 2 ===
{"decision": "ALLOWED", "reason": "All checks passed", "action_count": 2}

=== Attempt 3 ===
{"decision": "ALLOWED", "reason": "All checks passed", "action_count": 3}

=== Attempt 4 ===
{"decision": "BLOCKED", "reason": "Rate limit exceeded: max 3 per hour for volume_resize", "action_count": 3}
```

### CloudWatch Metrics Verification

```bash
# Guardrail decision metrics
aws cloudwatch get-metric-statistics \
  --namespace FSxNOps/Guardrails \
  --metric-name GuardrailDecision \
  --dimensions Name=Action,Value=volume_resize Name=Decision,Value=BLOCKED \
  --start-time $(date -u -v-1H +%Y-%m-%dT%H:%M:%S) \
  --end-time $(date -u +%Y-%m-%dT%H:%M:%S) \
  --period 300 \
  --statistics Sum \
  --region ap-northeast-1
```

### DynamoDB State Verification

```bash
# Check the guardrail state table record
aws dynamodb get-item \
  --table-name ${PREFIX}-guardrail-state \
  --key '{"action_name": {"S": "volume_resize"}}' \
  --region ap-northeast-1
```

### Expected DynamoDB Record

```json
{
  "action_name": {"S": "volume_resize"},
  "action_count": {"N": "3"},
  "window_start": {"S": "2026-05-23T10:00:00Z"},
  "last_execution": {"S": "2026-05-23T10:05:00Z"},
  "ttl": {"N": "1716544800"}
}
```

### Screenshot Capture Points

- [ ] Lambda execution logs (ALLOWED → BLOCKED transition)
- [ ] DynamoDB table record (with TTL)
- [ ] CloudWatch metrics showing BLOCKED count

## 5. Voice Chat WebRTC Verification

### Prerequisites

- Deployed with `enableVoiceChat=true`
- Pipecat Voice Agent deployed to AgentCore Runtime (via CLI)
- KVS Signaling Channel created

### Test Procedure

1. Access the CloudFront URL and sign in
2. Click the microphone icon on the chat screen
3. Verify the flow: voice input → text conversion → RAG search → voice output

### Verification Points

| Step | What to Verify |
|------|---------------|
| WebRTC connection | Connection established via KVS Signaling Channel |
| Voice input | Audio captured from microphone |
| STT | Audio converted to text |
| RAG search | KB search executed with the converted text |
| TTS | Search results returned as audio |
| Fallback | Automatic switch to REST API when WebRTC fails |

### Screenshot Capture Points

- [ ] Voice Chat UI (during microphone input)
- [ ] KVS Signaling Channel console screen
- [ ] Logs showing WebRTC → REST fallback
