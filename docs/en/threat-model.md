## Overview

This document is a threat model that organizes the major threats, attack vectors, impacts, existing mitigations, and recommended additional countermeasures for the Permission-aware Agentic RAG system.

---

## System Boundaries and Trust Boundaries

```
┌─────────────────────────────────────────────────────────────────────────┐
│ Trust Boundary 1: Internet → CloudFront                                  │
│  Attackers: External users, bots, scripts                                │
├─────────────────────────────────────────────────────────────────────────┤
│ Trust Boundary 2: CloudFront → Lambda (WebApp)                           │
│  Attackers: Authenticated but unauthorized users                         │
├─────────────────────────────────────────────────────────────────────────┤
│ Trust Boundary 3: Lambda → Bedrock / DynamoDB / FSx                      │
│  Attackers: Insider threats, misconfigurations, supply chain              │
├─────────────────────────────────────────────────────────────────────────┤
│ Trust Boundary 4: FSx for ONTAP → S3 Access Point → Bedrock KB               │
│  Attackers: Privilege escalation, metadata tampering                     │
└─────────────────────────────────────────────────────────────────────────┘
```

## Threat Catalog

### T1: Prompt Injection

| Item | Details |
|------|---------|
| **Threat** | Malicious prompts cause the system to ignore system prompts, bypass permission checks, or disclose unintended information |
| **Attack Vector** | User input → Converse API / Agent |
| **Impact** | High — Leakage of unauthorized document content, alteration of system behavior |
| **Existing Mitigations** | Bedrock Guardrails (content filters), SID filtering is performed on the application side (cannot be bypassed by LLM) |
| **Additional Recommendations** | Enable Guardrails Prompt Attack filter, input length limits, add output validation layer |
| **Residual Risk** | Indirect Prompt Injection (instructions embedded within documents) cannot be fully prevented |

**Important**: In this system, SID filtering is executed outside the LLM (at the application layer), so Prompt Injection cannot bypass the permission checks themselves. However, the risk remains that information within permitted documents could be disclosed in unintended ways.

---

### T2: Retrieval Poisoning

| Item | Details |
|------|---------|
| **Threat** | Malicious documents placed in FSx volumes contaminate RAG search results |
| **Attack Vector** | CIFS/SMB access → FSx volume → S3 AP → Bedrock KB |
| **Impact** | Medium to High — Generation of misinformation, phishing redirection, indirect Prompt Injection |
| **Existing Mitigations** | NTFS ACL write restrictions, Transfer Family IAM role restrictions, `.metadata.json` can only be generated by service role |
| **Additional Recommendations** | Malware scanning on document ingestion, content validation pipeline, anomaly detection (alerts for sudden document increases) |
| **Residual Risk** | Intentional contamination by internal users with legitimate write permissions |

---

### T3: Cross-User Data Leakage

| Item | Details |
|------|---------|
| **Threat** | User A's search results include documents that only User B should have access to |
| **Attack Vector** | SID filtering implementation bugs, cache poisoning, session confusion |
| **Impact** | High — Confidential information leakage, compliance violations |
| **Existing Mitigations** | SID matching (set intersection), Fail-Closed principle, permission matrix tests (31 scenarios) |
| **Additional Recommendations** | Automated periodic permission matrix test execution, anomaly detection (access patterns to normally unaccessed documents) |
| **Residual Risk** | Low — Since SID filtering is executed outside the LLM, bypass is difficult except through implementation bugs |

---

### T4: Stale ACL / Permission Drift

| Item | Details |
|------|---------|
| **Threat** | File ACLs are changed but stale permissions remain in vector store metadata or permission cache |
| **Attack Vector** | ACL change → Metadata not updated → Searchable with old permissions |
| **Impact** | Medium — Access remains possible for a period after permission revocation (up to 35 minutes) |
| **Existing Mitigations** | KB Auto-Sync (15-minute intervals), permission cache TTL (5 minutes), emergency permission revocation procedure |
| **Additional Recommendations** | Immediate ACL change event detection (FSx Audit Log → EventBridge), consider shorter cache TTL, permission change audit log |
| **Residual Risk** | Complete real-time reflection is impossible due to the Eventually Consistent model. Manual revocation handles emergencies |

**Details**: See [permission-consistency.md](../permission-consistency.md)

---

### T5: Over-Permissive Cache

| Item | Details |
|------|---------|
| **Threat** | Permission cache becomes fixed in an overly permissive state, continuing to allow access that should be denied |
| **Attack Vector** | Race conditions during cache writes, TTL misconfiguration, cache key collisions |
| **Impact** | High — Continuous access to unauthorized documents |
| **Existing Mitigations** | DynamoDB TTL automatic expiration (5 minutes), cache key includes user ID + document ID |
| **Additional Recommendations** | Monitor cache hit rate, alert on abnormally high hit rates, periodic full cache clear (daily) |
| **Residual Risk** | Low — Due to short TTL, automatic recovery within 5 minutes even if contaminated |

---

### T6: Agent Tool Abuse

| Item | Details |
|------|---------|
| **Threat** | Agent invokes unintended tools, performing data modification, deletion, or external transmission |
| **Attack Vector** | Prompt Injection → Agent action plan alteration → Dangerous tool invocation |
| **Impact** | High — Data destruction, information leakage, cost explosion |
| **Existing Mitigations** | AgentCore Policy (tool access restrictions), Action Group IAM role least privilege, only read-only tools provided by default |
| **Additional Recommendations** | Human Approval (approval before external action execution), tool invocation count limits, cost caps |
| **Residual Risk** | Medium — Trade-off between Agent autonomy and safety. Risk is low if restricted to read-only |

---

### T7: Audit Log Tampering

| Item | Details |
|------|---------|
| **Threat** | Tampering or deletion of audit logs to conceal evidence of unauthorized access |
| **Attack Vector** | Lambda execution role privilege escalation → CloudWatch Logs / S3 tampering |
| **Impact** | High — Inability to investigate incidents, compliance violations |
| **Existing Mitigations** | CloudWatch Logs retention policies, IAM least privilege |
| **Additional Recommendations** | S3 Object Lock (WORM), CloudTrail log storage in separate account, log integrity verification (CloudTrail Digest) |
| **Residual Risk** | Low — Practically tamper-proof with S3 Object Lock + separate account storage |

**Details**: See [governance-and-audit.md](../governance-and-audit.md)

---

### T8: Misconfigured Identity Federation

| Item | Details |
|------|---------|
| **Threat** | OIDC / SAML / LDAP misconfiguration allows unauthorized users to pass authentication, or grants excessive permissions to legitimate users |
| **Attack Vector** | IdP misconfiguration → Unauthorized token issuance → Cognito authentication bypass → Excessive SID assignment |
| **Impact** | High — Privilege escalation, access to all documents |
| **Existing Mitigations** | `authFailureMode=fail-closed` (block on permission retrieval failure), Cognito token validation, LDAP health check |
| **Additional Recommendations** | Periodic IdP configuration audits, automatic federation metadata validation, alerts for abnormal group SID counts |
| **Residual Risk** | Medium — IdP-side configuration is outside this system's control. Fail-Closed limits the impact |

---

### T9: Vector Metadata Leakage

| Item | Details |
|------|---------|
| **Threat** | Vector store metadata (SID information, file paths) is unintentionally exposed, leaking organizational structure and access permission information |
| **Attack Vector** | Direct access to S3 Vectors / OpenSearch Serverless, excessive information in API responses |
| **Impact** | Medium — Inference of organizational structure, information gathering for targeted attacks |
| **Existing Mitigations** | VPC endpoint access restrictions, IAM policy prevention of direct access, SID information excluded from API responses (frontend) |
| **Additional Recommendations** | Least privilege S3 Vectors bucket policy, OpenSearch Serverless data access policy audit, metadata encryption |
| **Residual Risk** | Low — Only access via Bedrock KB is permitted, direct access prevented by IAM |

---

### T10: Denial of Wallet / Cost Abuse

| Item | Details |
|------|---------|
| **Threat** | Massive requests or intentional use of high-cost models to explode AWS billing |
| **Attack Vector** | Mass queries by authenticated users, infinite loops in Agent mode, continuous use of high-cost models |
| **Impact** | High — Unexpected high charges |
| **Existing Mitigations** | WAF rate limit (2000 req/5min), Smart Routing (low-cost model priority), Lambda concurrency limits |
| **Additional Recommendations** | AWS Budgets alerts, per-user daily query limits, Agent step count limits, consider Bedrock Provisioned Throughput |
| **Residual Risk** | Medium — Mitigated by rate limits, but excessive use by legitimate users cannot be fully prevented |

## Recommended Additional Countermeasures (Priority Order)

### Immediate Response (P1)

1. **Enable Guardrails Prompt Attack filter** — T1 countermeasure
2. **Implement Human Approval for Agent tool invocations** — T6 countermeasure
3. **Establish periodic IdP configuration audit process** — T8 countermeasure
4. **Integrate permission matrix tests into CI/CD** — T3 countermeasure

### Short-term Response (P2)

5. **Protect audit logs with S3 Object Lock** — T7 countermeasure
6. **Immediate ACL change event detection** — T4 countermeasure
7. **Content validation on document ingestion** — T2 countermeasure
8. **AWS Budgets + per-user query limits** — T10 countermeasure

### Medium-term Response (P3)

9. **Cache hit rate anomaly detection** — T5 countermeasure
10. **Vector store metadata encryption** — T9 countermeasure
