## 1. Verificación de Smart Routing

### Procedimiento de prueba

1. Acceda a la URL de CloudFront e inicie sesión como usuario admin
2. Active **Smart Routing** en la configuración del chat
3. Envíe los siguientes 3 tipos de consultas y verifique los resultados de enrutamiento

### Consultas de prueba y resultados esperados

| Consulta | Nivel esperado | Modelo esperado | Punto de verificación |
|--------|-----------|-----------|-------------|
| «Hola» | Simple | Haiku 4.5 | Los metadatos de respuesta contienen `routingTier: simple` |
| «Resuma el contenido del catálogo de productos» | Complex | Sonnet 3.5 v2 | Los metadatos de respuesta contienen `routingTier: complex` |
| «Analice de forma transversal los informes trimestrales de todos los departamentos e identifique oportunidades de reducción de costes» | Full-context | Opus 4 | Los metadatos de respuesta contienen `routingTier: full-context` |

### Verificación de métricas de CloudWatch

```bash
# Verificar la distribución de enrutamiento (última hora)
aws cloudwatch get-metric-statistics \
  --namespace SmartRouting \
  --metric-name RoutingCount \
  --dimensions Name=RoutingTier,Value=simple \
  --start-time $(date -u -v-1H +%Y-%m-%dT%H:%M:%S) \
  --end-time $(date -u +%Y-%m-%dT%H:%M:%S) \
  --period 300 \
  --statistics Sum \
  --region ap-northeast-1
```

### Salida esperada de CloudWatch Logs

```json
{
  "level": "INFO",
  "message": "Smart routing decision",
  "query": "Hola",
  "classification": "simple",
  "confidence": 0.95,
  "selectedModel": "anthropic.claude-haiku-4-5-20251001-v1:0",
  "queryWordCount": 1,
  "hasAnalyticalTerms": false
}
```

### Puntos de captura de pantalla

- [ ] Interfaz de chat mostrando el nivel de enrutamiento
- [ ] Panel de métricas de CloudWatch con el gráfico de distribución de enrutamiento
- [ ] Comparación de tiempos de respuesta entre los 3 niveles (misma pregunta)

## 2. Verificación de Transfer Family IAM Deny

### Procedimiento de prueba

Verifique que los usuarios partner no puedan sobrescribir los archivos `.metadata.json`.

```bash
# 1. Conexión SFTP
sftp -i /path/to/partner-key \
  -o HostKeyAlgorithms=rsa-sha2-256,rsa-sha2-512 \
  partner-a@s-XXXXXXXXXXXXXXXXX.server.transfer.ap-northeast-1.amazonaws.com

# 2. Carga de archivo normal (debería funcionar)
sftp> put test-document.pdf /uploads/partner-a/test-document.pdf

# 3. Intento de sobrescribir .metadata.json (debería denegarse)
sftp> put fake-metadata.json /uploads/partner-a/test-document.pdf.metadata.json
```

### Resultados esperados

```
# Archivo normal: Éxito
Uploading test-document.pdf to /uploads/partner-a/test-document.pdf
test-document.pdf                                    100%  1234     12.3KB/s   00:00

# .metadata.json: Access Denied
Uploading fake-metadata.json to /uploads/partner-a/test-document.pdf.metadata.json
remote open("/uploads/partner-a/test-document.pdf.metadata.json"): Permission denied
```

### Verificación en CloudTrail

```bash
# Verificar eventos Access Denied
aws cloudtrail lookup-events \
  --lookup-attributes AttributeKey=EventName,AttributeValue=PutObject \
  --start-time $(date -u -v-1H +%Y-%m-%dT%H:%M:%S) \
  --region ap-northeast-1 \
  --query 'Events[?contains(CloudTrailEvent, `AccessDenied`)].{Time:EventTime,User:Username}'
```

### Puntos de captura de pantalla

- [ ] Terminal SFTP mostrando una carga de archivo normal exitosa
- [ ] Terminal SFTP mostrando la carga de `.metadata.json` denegada
- [ ] Evento Access Denied en CloudTrail

## 3. Verificación de KB Auto-Sync

### Procedimiento de prueba

1. Añada un archivo de prueba al S3 Access Point
2. Verifique que se ejecute un escaneo en un plazo de 5 minutos
3. Verifique que un trabajo de ingestión se inicie y se complete

```bash
# 1. Añadir un archivo de prueba al S3 AP
aws s3api put-object \
  --bucket arn:aws:s3:ap-northeast-1:ACCOUNT:accesspoint/AP_NAME \
  --key test-auto-sync/new-document.md \
  --body ./test-document.md \
  --region ap-northeast-1

# 2. Añadir el .metadata.json correspondiente
aws s3api put-object \
  --bucket arn:aws:s3:ap-northeast-1:ACCOUNT:accesspoint/AP_NAME \
  --key test-auto-sync/new-document.md.metadata.json \
  --body ./test-metadata.json \
  --region ap-northeast-1

# 3. Monitorizar los registros de Lambda (el escaneo debería ejecutarse en un plazo de 5 minutos)
aws logs tail /aws/lambda/${PREFIX}-kb-auto-sync \
  --follow --region ap-northeast-1
```

### Salida esperada del registro de Lambda

```json
{
  "level": "INFO",
  "message": "Scan completed",
  "scanId": "scan-20260523-103000",
  "filesScanned": 15,
  "newFiles": 1,
  "changedFiles": 0,
  "unchangedFiles": 14,
  "triggerIngestion": true
}
```

```json
{
  "level": "INFO",
  "message": "Ingestion job started",
  "jobId": "XXXXXXXXXX",
  "knowledgeBaseId": "XXXXXXXXXX",
  "dataSourceId": "XXXXXXXXXX"
}
```

### Verificación del inventario de DynamoDB

```bash
# Verificar los registros más recientes de la tabla de inventario
aws dynamodb scan \
  --table-name ${PREFIX}-kb-auto-sync-inventory \
  --limit 5 \
  --region ap-northeast-1 \
  --query 'Items[*].{Key:fileKey.S,ETag:etag.S,LastModified:lastModified.S}'
```

### Puntos de captura de pantalla

- [ ] CloudWatch Logs mostrando el registro de resultados del escaneo
- [ ] Registros de la tabla de inventario de DynamoDB (antes y después del escaneo)
- [ ] Consola de Bedrock KB mostrando el trabajo de ingestión completado

## 4. Verificación de Capacity Guardrails

### Procedimiento de prueba

Ejecute la misma acción en rápida sucesión para verificar que se activa la limitación de tasa.

```bash
# Invocar la Lambda de Guardrails directamente (para pruebas)
for i in 1 2 3 4; do
  echo "=== Attempt $i ==="
  aws lambda invoke \
    --function-name ${PREFIX}-capacity-monitor \
    --payload '{"action": "volume_resize", "volume_id": "vol-test", "new_size_gb": 100}' \
    --region ap-northeast-1 \
    /tmp/guardrail-response-$i.json
  cat /tmp/guardrail-response-$i.json
  echo ""
  sleep 2
done
```

### Resultados esperados

```
=== Attempt 1 ===
{"decision": "ALLOWED", "reason": "All checks passed", "action_count": 1}

=== Attempt 2 ===
{"decision": "ALLOWED", "reason": "All checks passed", "action_count": 2}

=== Attempt 3 ===
{"decision": "ALLOWED", "reason": "All checks passed", "action_count": 3}

=== Attempt 4 ===
{"decision": "BLOCKED", "reason": "Rate limit exceeded: max 3 per hour for volume_resize", "action_count": 3}
```

### Verificación de métricas de CloudWatch

```bash
# Métricas de decisión del guardrail
aws cloudwatch get-metric-statistics \
  --namespace FSxNOps/Guardrails \
  --metric-name GuardrailDecision \
  --dimensions Name=Action,Value=volume_resize Name=Decision,Value=BLOCKED \
  --start-time $(date -u -v-1H +%Y-%m-%dT%H:%M:%S) \
  --end-time $(date -u +%Y-%m-%dT%H:%M:%S) \
  --period 300 \
  --statistics Sum \
  --region ap-northeast-1
```

### Verificación del estado de DynamoDB

```bash
# Verificar el registro de la tabla de estado del guardrail
aws dynamodb get-item \
  --table-name ${PREFIX}-guardrail-state \
  --key '{"action_name": {"S": "volume_resize"}}' \
  --region ap-northeast-1
```

### Registro esperado de DynamoDB

```json
{
  "action_name": {"S": "volume_resize"},
  "action_count": {"N": "3"},
  "window_start": {"S": "2026-05-23T10:00:00Z"},
  "last_execution": {"S": "2026-05-23T10:05:00Z"},
  "ttl": {"N": "1716544800"}
}
```

### Puntos de captura de pantalla

- [ ] Registros de ejecución de Lambda (transición ALLOWED → BLOCKED)
- [ ] Registro de la tabla de DynamoDB (con TTL)
- [ ] Métricas de CloudWatch mostrando el recuento de BLOCKED

## 5. Verificación de Voice Chat WebRTC

### Requisitos previos

- Desplegado con `enableVoiceChat=true`
- Pipecat Voice Agent desplegado en AgentCore Runtime (mediante CLI)
- KVS Signaling Channel creado

### Procedimiento de prueba

1. Acceda a la URL de CloudFront e inicie sesión
2. Haga clic en el icono del micrófono en la pantalla de chat
3. Verifique el flujo: entrada de voz → conversión a texto → búsqueda RAG → salida de voz

### Puntos de verificación

| Paso | Qué verificar |
|---------|---------|
| Conexión WebRTC | Conexión establecida a través de KVS Signaling Channel |
| Entrada de voz | Audio capturado desde el micrófono |
| STT | Audio convertido a texto |
| Búsqueda RAG | Búsqueda KB ejecutada con el texto convertido |
| TTS | Resultados de búsqueda devueltos como audio |
| Reserva | Cambio automático a la API REST cuando WebRTC falla |

### Puntos de captura de pantalla

- [ ] Interfaz de Voice Chat (durante la entrada de micrófono)
- [ ] Pantalla de la consola de KVS Signaling Channel
- [ ] Registros mostrando la reserva WebRTC → REST
