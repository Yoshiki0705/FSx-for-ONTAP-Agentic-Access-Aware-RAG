## 事象の詳細

社内開発環境のCI/CDパイプラインにおいて、不正なnpmパッケージ（`@internal/auth-helper` のタイポスクワッティング版）がインストールされたことを検知しました。

### 影響範囲

- **影響を受けたシステム**: 開発環境のビルドサーバー3台
- **影響を受けたデータ**: 環境変数に含まれるAPIキー2件（AWS, GitHub）
- **本番環境への影響**: なし（ネットワーク分離により遮断）
- **顧客データへの影響**: なし

### 対応タイムライン

1. 14:23 - 不正パッケージがビルドサーバーにインストール
2. 14:45 - Snyk SCAアラートにより検知
3. 15:00 - セキュリティチームがインシデント宣言
4. 15:30 - 影響を受けたAPIキーを全て無効化・ローテーション
5. 16:00 - ビルドサーバーをクリーンイメージから再構築
6. 17:00 - 全パイプラインの依存関係を監査完了
7. 18:00 - インシデントクローズ

### 根本原因

`package.json` の依存関係に `@internal/auth-helpr`（正: `@internal/auth-helper`）が混入。開発者のタイプミスにより、悪意のあるパッケージがインストールされた。

### 再発防止策

- npm registry のスコープロック設定を全プロジェクトに適用
- `package-lock.json` の差分レビューを必須化
- 依存関係の許可リスト（allowlist）を導入
- 開発者向けサプライチェーンセキュリティ研修を実施（2025年12月）
